Build the first working MVP of an OpenCV AI Competition 2026 project called “Agentic Vision Pipeline Repair”.

IMPORTANT: This is a technical proof of concept, not a generic AI dashboard. Prioritize a working, reproducible end-to-end experiment over visual polish.

## Product objective

Build an autonomous vision-pipeline testing and repair application. It should discover where an image-processing pipeline fails, choose a configuration change based on measured results, apply the change, and verify whether the repair generalizes to a held-out test set.

The application must use OpenCV substantively. It must not merely send images to an LLM or display simulated performance numbers.

## Technology stack

- Python 3.11 or another Replit-supported Python version compatible with OpenCV 5
- Streamlit for the initial UI
- NumPy
- OpenCV Python bindings, preferably version 5.0.0.93
- Matplotlib for optional visualizations
- pytest for automated tests

Use `opencv-python-headless` for the server environment. Verify the installed version at startup. Do not silently downgrade to OpenCV 4 and claim OpenCV 5 compliance. If OpenCV 5 cannot be installed, report the exact error and keep the dependency issue visible.

Do not require an OpenAI API key or any paid API for this first milestone. The initial agent must make actual decisions based on measured experiment results.

## Core experiment

Create a reproducible synthetic image dataset containing colored circular targets on varied backgrounds.

Every image must have ground-truth labels describing the target's location and size. Generate independent training, validation, and held-out test sets using fixed, documented random seeds.

Vary the image conditions, including:
- Normal lighting
- Low brightness and high brightness
- Blur
- Color shifts
- Noise
- Different target sizes and positions
- Distracting background shapes

The labels must remain correct after image transformations. Keep the target visible in the initial experiment so detection failures can be evaluated consistently.

## Baseline vision pipeline

Implement a genuine OpenCV pipeline using operations such as:
- Color-space conversion
- HSV thresholding
- Morphological filtering
- Contour extraction
- Circle candidate detection
- Matching predictions to ground-truth targets

Return predicted bounding regions, confidence or quality measurements where appropriate, and per-image results.

Measure precision, recall, F1 score, and failure rate. Define how predictions are matched to ground truth and document the matching rule. Avoid inflated scores caused by duplicate detections.

## Autonomous repair agent

Implement a bounded, reproducible agent that can:

1. Run the baseline pipeline on the validation dataset.
2. Group failures by image conditions.
3. Identify which conditions cause the greatest performance loss.
4. Select a relevant processing parameter or combination of parameters to investigate.
5. Invoke OpenCV experiments using candidate configurations.
6. Evaluate each experiment on validation data.
7. Update its next experiment based on the measured results.
8. Stop when it reaches a defined experiment budget or no meaningful improvement is found.
9. Save the selected configuration and an auditable trace of decisions, experiments, metrics, and stopping conditions.

The agent must actually execute experiments and use their results to determine subsequent actions. Do not hard-code a winning configuration or fabricate agent reasoning.

Keep the search space bounded so experiments finish quickly in Replit. Record the number of experiments performed.

## Leakage prevention and honest evaluation

Do not use held-out test images to select parameters.

After the agent selects its final configuration, evaluate the baseline and repaired pipeline on exactly the same untouched test images.

Include:
- Baseline validation and test metrics
- Repaired validation and test metrics
- Absolute and relative metric changes
- Performance broken down by image condition
- Failure cases and regressions
- Runtime and experiment count
- Random seeds and configuration details

The system must be allowed to conclude that no repair was successful. Never manufacture a positive result.

## Streamlit interface

Create a clean interface with these sections:

1. Overview: project purpose and installed OpenCV version.
2. Dataset: preview representative generated images and their ground-truth labels.
3. Baseline: run the initial pipeline and inspect failures.
4. Agent run: start the repair process and display experiment progress.
5. Results: compare baseline and repaired performance using actual measured data.
6. Failure analysis: inspect examples where the repair succeeded, failed, or caused regressions.
7. Agent trace: show the experiments, decisions, configurations, and metrics in chronological order.
8. Export: download a JSON experiment report and CSV per-image results.

Use clear status indicators for running, completed, failed, and inconclusive experiments.
